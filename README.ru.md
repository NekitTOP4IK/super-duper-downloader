# super-duper-downloader

[English](README.md) · **Русский**

Пет-проект в разработке: загрузчик, который может загрузить почти (нет) всё.

Вставил ссылку, получил файл. Веб-загрузчик публичных медиа, который запускается на
своём сервере: YouTube, TikTok, Instagram, X, VK, SoundCloud и остальные
[сайты, которые поддерживает yt-dlp](https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md),
плюс прямые ссылки на файлы.

- По ссылке показывается превью и только те качества, которые у медиа реально есть:
  best, 1080p, 720p, 480p или аудио, у каждого примерный размер, если сайт отдаёт
  достаточно данных. Качество меряется по короткой стороне, поэтому 720p у вертикального
  видео — это 720x1280. Видео приходит в H.264 с AAC, если сайт такое отдаёт, чтобы
  играло везде.
- Аудио — это звуковая дорожка самого сайта. Если отдельной дорожки нет, звук
  вынимается из видео без перекодирования.
- Пакетный режим берёт до 50 ссылок за раз, вставленных или загруженных из `.txt`, и
  отдаёт всё одним zip.
- Плейлисты раскладываются на отдельные загрузки, а пост с несколькими видео, например
  карусель в Instagram, скачивается одной загрузкой с файлом на каждое видео. Прогресс
  идёт вживую, список загрузок переживает перезагрузку страницы.
- Интерфейс в стиле терминала, на русском или английском, с 23 цветовыми темами и
  четырьмя моноширинными шрифтами.

## Запуск

Нужен Docker с Compose v2.

```sh
git clone https://github.com/NekitTOP4IK/super-duper-downloader.git
cd super-duper-downloader
cp .env.example .env
docker compose up -d --build
```

Сайт откроется на <http://localhost>. Чтобы отдавать его на домене, укажи этот домен в
`SITE_ADDRESS` в `.env`: Caddy сам получит сертификат, если порты 80 и 443 доступны из
интернета.

> [!WARNING]
> Аккаунтов и лимитов на пользователя пока нет. Любой, кто может открыть страницу,
> может качать через твой сервер, расходуя его трафик и диск. Лимиты ниже общие на
> всех.

### За другим веб-сервером

Если порты 80 и 443 уже заняты веб-сервером, например nginx, опубликуй Caddy на
локальном порту в `docker-compose.override.yml` рядом с `docker-compose.yml`:

```yaml
services:
  caddy:
    ports: !override
      - "127.0.0.1:18090:80"
```

Потом проксируй домен на `127.0.0.1:18090` с того сервера, отключив буферизацию ответов
(`proxy_buffering off` в nginx): прогресс загрузки идёт потоком событий.

## Настройка

Всё лежит в `.env`.

| Переменная | По умолчанию | Что это |
| --- | --- | --- |
| `SITE_ADDRESS` | `:80` | Адрес, который отдаёт Caddy: `:80` для HTTP или домен для HTTPS |
| `PROXY_URL` | пусто | Прокси для yt-dlp и прямых загрузок, например `socks5://host:1080` |
| `EGRESS_ALLOW_CIDRS` | пусто | Сети, куда воркерам можно ходить, хоть они и выглядят частными, см. ниже |
| `MAX_DURATION_SEC` | `10800` | Самое длинное медиа, которое принимается |
| `MAX_FILESIZE_MB` | `2048` | Самый большой файл, который принимается |
| `MAX_BATCH_URLS` | `50` | Сколько ссылок берётся из одного запроса |
| `MAX_PLAYLIST_ITEMS` | `50` | Сколько элементов берётся из одного плейлиста |
| `MAX_QUEUE` | `500` | Сколько загрузок может ждать, прежде чем новые начнут отклоняться |
| `MAX_PROBE_QUEUE` | `100` | Сколько превью может ждать, прежде чем новые начнут отклоняться |
| `MIN_FREE_DISK_GB` | `5` | Свободное место, ниже которого новые загрузки отклоняются |
| `WORKER_CONCURRENCY` | `3` | Сколько загрузок идёт одновременно |
| `PROBE_CONCURRENCY` | `10` | Сколько превью идёт одновременно |
| `JOB_TIMEOUT_SEC` | `1800` | Сколько времени может занять одна загрузка |
| `FILE_TTL_HOURS` | `6` | Сколько хранятся готовые файлы |

### Сайты, которые не пускают серверы

Некоторые сайты отвечают сетям хостингов и VPN страницей блокировки вместо медиа.
Reddit отдал её всем клиентам, которых пробовали с такого адреса, включая имитацию
браузера, а Bilibili, Rumble и Vimeo тоже отказали. Резидентный прокси в `PROXY_URL`
помогает yt-dlp и прямым загрузкам. cobalt эту переменную не читает: он берёт HTTP-прокси
из `HTTP_PROXY` или `HTTPS_PROXY`, заданных в его собственном `environment` в
`docker-compose.yml`.

## Как это устроено

Caddy отдаёт интерфейс и передаёт `/api` в сервис на FastAPI. Превью и загрузки идут
через очереди в Redis к отдельным воркерам. Воркер сначала пробует yt-dlp, потом
[cobalt](https://github.com/imputnet/cobalt) (он работает в своём контейнере), потом
обычную HTTP-загрузку для прямых ссылок на файлы. Если не справился никто, пользователь
видит самую конкретную причину, например «нужен вход». Готовые файлы удаляются через
`FILE_TTL_HOURS`.

## Безопасность

Воркеры открывают любой URL, который вставил пользователь, поэтому они не подключаются
к частным, loopback, link-local и другим непубличным адресам, включая адрес метаданных
облака. Redis и cobalt доступны коду самого сервиса, но не тому, куда ведёт
пользовательский URL, включая редиректы. Несколько вещей эта защита не покрывает:

- **`EGRESS_ALLOW_CIDRS`.** Некоторые прокси (Clash, sing-box в режиме fake-ip)
  резолвят любой домен в `198.18.0.0/15`, который выглядит частным и блокируется. Если
  указать этот диапазон, загрузки заработают, но всё в нём станет доступно и для
  пользовательских URL. Указывай только сети, в которых нет ничего твоего.
- **`PROXY_URL`.** С прокси защита видит только подключение к прокси, а куда идут
  запросы, решает сам прокси. Используй такой, который не достаёт до твоей внутренней
  сети.
- **ffmpeg.** Когда yt-dlp передаёт поток в ffmpeg, тот подключается сам, и его никто
  не проверяет.
- **Имитация браузера.** TikTok и ещё некоторые сайты отвечают только клиентам, похожим
  на браузер, поэтому yt-dlp шлёт такие запросы через curl_cffi, который подключается в
  обход Python и тоже не проверяется. Так делают только экстракторы отдельных сайтов и
  только к своим хостам, но дальше curl сам проходит до пяти редиректов.

## Разработка

```sh
docker compose -f docker-compose.dev.yml up -d --build
```

Это поднимает API на порту 8000 и перезапускает его и воркеры, когда меняются файлы в
`backend/app`. Потом запусти интерфейс, он проксирует `/api` на этот порт:

```sh
cd frontend
npm ci
npm run dev
```

Проверки, те же, что гоняет CI. В `backend`:

```sh
uv run pytest
uv run ruff check .
uv run ruff format --check .
```

`uv run pytest -m network` добавляет несколько тестов, которые ходят на настоящие
сайты. Во `frontend`:

```sh
npm test
npm run build
```
